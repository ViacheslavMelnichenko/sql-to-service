# 0004 — Claude Code як субстрат: справжні агенти, скіли, хуки, тули

- **Статус:** Accepted
- **Дата:** 2026-08-07
- **Ухвалив:** Viacheslav Melnichenko

## Контекст

Теза — «інженерія *навколо* AI», тож агентна машинерія має бути справжньою, не
слоганом. Тонкий Python-скрипт, що смикає model API в циклі й називає свої функції
«agent» і «hook», був би саме тим, кращим за що цей артефакт існує. Рев'ювер, на
якого ми цілимось, бачить різницю з першого погляду.

## Драйвери рішення

- Чотири примітиви (субагенти, скіли, хуки, тули) мають бути *реальними механізмами
  платформи*, тож ярлики підкріплені реальністю, а не перейменованим кодом.
- Розділення контексту між стадіями має бути структурним, не симульованим обрізанням
  рядка промпту.
- Цільовий рев'ювер має впізнати власні інструменти, відкривши репо.

## Розглянуті опції

1. **Framework-agnostic тонкий оркестратор.** Саморобний цикл із нашими
   абстракціями «agent»/«hook». Відхилено — примітиви були б нашими, визначеними
   вільно, і сеньйор відкрив би й знайшов непідкріплені ярлики. Вищий ризик
   читатись як «скрипт, що вдає агента».
2. **Загальний агентний фреймворк (LangGraph / подібний).** Відхилено для цього
   артефакту — додає залежність, чиї примітиви мапляться не так чисто, і це не та
   платформа, яку оцінює аудиторія.
3. **Будувати на Claude Code — субагенти, скіли, хуки, тули нативні.** Обрано.

## Рішення

Пайплайн побудований **на Claude Code**, на його нативних примітивах:

- **Субагенти** (`.claude/agents/*.md`) — по одному на стадію (`analyst`,
  `implementer`, `test-author`, `reviewer`), кожен зі своїм системним промптом,
  моделлю і тулсетом. Розділення контексту вбудоване в платформу, не імітоване.
- **Скіли** (`.claude/skills/*`) — стандарти конверсії як версіоновані файли, які
  `reviewer` завантажує і перевіряє.
- **Хуки** (`.claude/settings.json`) — `PostToolUse`, `Stop`, `PreToolUse` гейтять
  переходи автоматично, в потоці.
- **Тули** — детерміновані гейт-скрипти, які агенти викликають (див. ADR-0005).

**Обмеження чесності:** відмінність agent/stage/tool має бути *реальною в коді*.
Якщо `analyst` і `implementer` — справді різні системні промпти з різними тулсетами
і розділеним контекстом, вони чесно «агенти». Якщо якась відмінність виявиться
косметичною, ми перейменовуємо її на те, чим вона є («стадія»), а не даємо
непідкріпленому ярлику коштувати дорожче потім.

## Наслідки

- **Плюс:** примітиви підкріплені механізмом платформи; `.claude/` стає першокласним
  експонатом, який рев'ювер упізнає.
- **Плюс:** хуки дають in-loop гейтинг задарма — твердження «гейтити кожен перехід»
  це фіча платформи, не наша сантехніка.
- **Ціна:** прив'язує артефакт до Claude Code; відтворення потребує його.
  Прийнятно — аудиторія оцінює саме цей субстрат.
- **Ціна:** ганяти реального агента headless на процедуру (для харнеса) нетривіально,
  але саме це робить виміряні числа чесними (це проблема харнеса; див. METHOD).
